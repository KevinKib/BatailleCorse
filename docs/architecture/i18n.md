# Internationalisation (English and French)

## Shape

- `frontend/src/locales/Messages.ts` is the type of every visible text; `en.ts` is the English bundle (loaded with the app), `fr/` the French one (one file per area group, composed in `fr/index.ts`, loaded on demand with `import('./fr')`).
- `locales/index.ts`: `SUPPORTED_LOCALES` (the languages a player can choose), `loadMessages`.
- `locales/locale.ts`: `initLocale()` runs before the app mounts. It picks the locale (saved `bc_locale`, then `navigator.languages`, then English), loads its bundle, and sets `<html lang>`. `setLocale()` saves the choice and reloads the page, so the whole UI boots in one language. English is the fallback if the French chunk fails to load.
- `components/LanguagePicker.vue` (globe menu on the game picker, segmented row in the settings panel) renders only when several locales are offered.

## Adding or changing a text

1. Add the key in `Messages.ts` and `en.ts`, and its French in the matching `fr/*.ts` file.
2. `parity.test.ts` checks: same keys and array lengths, same `{placeholders}`, same rules-section kinds, no empty or still-English French leaf (except `SAME_AS_ENGLISH_ALLOWED`: proper nouns, symbols), French typography (narrow no-break space before `; ! ? »` and after `«`, no-break space before `:`, `’` and `…`), and no U+FFFD.
3. `length.test.ts` lists short French strings more than 60% longer than English; check them at 375 px.

## Conventions

French uses "vous", "bataille corse" in lower case, plural forms where 0 is singular (see `locales/format.ts`). Names typed by players are never translated; an unnamed seat is "Player N" / "Joueur N", a computer seat "Bot N", built by `model/table/displayName.ts` from translated labels.

## Known gaps

Texts that come from the backend (seat names when unnamed, bot names, public-list host fallback) are still English until the backend sends no name for those seats and the frontend builds the fallback.
